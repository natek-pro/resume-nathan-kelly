## Wording assessment

| Wording | Assessment |
| --- | --- |
| Designed | Retained on Nathan’s supplied evidence of agent specialization, shared state, scheduling, handoffs, and approval-gate design. Refers to the workflow, not the underlying framework. |
| Operate | Retained as an ongoing activity stated in the supplied description. Does not assert autonomous operation. |
| Full job search | Removed: unnecessarily broad and could imply every stage, including final submissions, is autonomous or covered by this system. |
| Integrated | Replaced with the role Codex CLI serves. Without implementation details, this could suggest Nathan coded an API or software integration. |
| System | Changed to Workflow in the title to keep the contribution centered on orchestration of existing tools. |
| Shared Postgres data | Compresses the supplied shared jobs-database fact; does not assert that Nathan wrote the schema or database software. |
| Human approval before each submission | Keeps the specific control boundary; does not claim that the agents submit applications autonomously. |
| Framework development, coded API integrations, production agent infrastructure, tool-calling implementation | Not claimed. These require additional evidence before being attributed to Nathan. |

The agent specialties remain documented in the supplied original rather than listing all four in the short resume entry. The same factual entry serves Applied AI as orchestration evidence and FDE as workflow/system-design evidence; it is a personal project, not customer delivery.
